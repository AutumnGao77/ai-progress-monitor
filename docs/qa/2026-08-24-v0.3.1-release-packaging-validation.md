## GitHub 附件闭环

1. 在用户确认标题和正文后推送不可移动的 `v0.3.1` annotated tag。
2. 创建 Draft Release，只上传 macOS 和 portable 两个最终 ZIP。
3. GitHub 服务端摘要与本地最终 SHA-256 一致。
4. 两个附件下载到独立临时目录，不覆盖本地 `dist/`。
5. GitHub CDN 多次超时时采用固定 Range 分段续传；每段长度正确才写入，最终文件大小和 SHA-256 必须完整匹配。
6. 回下载副本分别通过 ZIP 完整性与逐字节比较，和本地最终包完全一致。
7. 用户检查 Draft 页面、标题、正文和两个附件后明确授权发布。
8. 发布后复核 `isDraft=false`、`isPrerelease=false`、Latest 为 `v0.3.1`，正文和两个附件对象未变化。

GitHub 会将本次分段 Range 请求分别计入附件 `download_count`，因此该计数包含维护者的验包流量，不代表外部用户下载人数，也不作为发布验收指标。
