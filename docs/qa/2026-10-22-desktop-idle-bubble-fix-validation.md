# v0.3.4 空闲气泡与原生窗口修复验收

发布基线为 v0.3.3，并纳入主分支提交 `f415a9e67a37f8bc36fbf7fef1e9475216567475` 的发布验收记录。修复分支为 `codex/fix-v033-idle-conversations`。最终发布状态、源码提交与附件校验和以 v0.3.4 的 GitHub Release 为准。

## 本次产品规则

用户明确确认：所有 AI 工具遵循同样的规则，包含 ChatGPT 和终端中的 Claude / Codex 等 CLI。

| 条件 | 期望结果 |
| --- | --- |
| 具体对话连续空闲不足 15 分钟 | 保留具体对话气泡 |
| 具体对话空闲满 15 分钟 | 移出具体对话；工具仍存活时，同一产品只保留一个空闲入口 |
| 已查看的完成结果 | 从查看时间计时；新任务不得继承旧任务的查看时间 |
| 明确的空闲事件 | 使用当前来源事件时间，较新的事件不受旧查看时间影响 |
| 只有进程活跃度证据的 CLI | 用单调时钟记录连续观察到的空闲时长，扫描心跳不重置计时 |
| 工具出现新活动 | 恢复具体对话，下一次转空闲时重新计时 |
| 运行中或真正等待用户操作 | 不按空闲规则回收 |
| 工具进程退出 | 移除对应入口；历史 JSON 或 wrapper 记录不作为存活证据 |
| 同产品的多个后台进程或桌面与 CLI 同时存活 | 通用空闲入口最多一个；真实对话仍各自显示 |
| 点击已收起对话的工具入口 | 保留正常聚焦能力，不重新展开过期对话 |

Qoder 与 Qoder CN 是不同产品。规则只影响气泡，不结束 AI 工具进程。连续空闲计时只保存在内存中，不保存会话正文。

## 缺陷与修复

- Qoder / Qoder CN 的搜索、知识库和插件服务复用主可执行文件，导致额外桌面入口。工具注册表排除已确认的辅助服务。
- WorkBuddy 预热 CLI 未被原有后台服务过滤规则覆盖，导致第二个空闲气泡。补齐预热模式过滤，保留普通 CLI 集成。
- 旧空闲回收只覆盖已查看的桌面对话。现在覆盖所有工具、桌面与 CLI，并保留旧式 App 空闲入口的兼容识别。
- 已查看旧任务之后开始新任务时，旧查看时间可能导致新空闲阶段立即过期。已修正并补充回归。
- 2026-10-22 17:09（Asia/Shanghai）的本地崩溃报告确认：后台输出回调在 `AppDelegate.writeLog` 的旧式 FileHandle 写入中抛出异常，导致原生 App 退出并留下后台进程。日志写入与关闭现由锁串行保护，使用可捕获错误的 Swift API；日志不可写时安全降级。

## 本机验证

- 构建开发 App，验证签名及包内源码一致性后启动。确认原生窗口进程和对应 Python 后端均存活，不能只用 HTTP 响应认定启动成功。
- 原生界面实际展开后，Qoder、Qoder CN、WorkBuddy 各显示一个空闲入口；真实运行和待操作会话独立保留。
- 精确终止候选 Python 后端后，原生窗口保持同一进程，自动启动新后端，接口与气泡列表恢复。
- 正常菜单退出同时清理原生窗口和对应后端，无新增崩溃报告；重新启动后原生窗口、后端和接口均恢复。
- 用户偏好前后哈希一致。旧正式 App 和测试版恢复备份保留在本地忽略目录。

15 分钟边界由可控时钟回归验证，不宣称逐一对每个第三方工具完成真实等待 15 分钟的手工操作。未重启 Qoder 或 WorkBuddy、未向其发起新任务。Windows 保持轻量预览，不宣称完成 Windows 实机验收。
